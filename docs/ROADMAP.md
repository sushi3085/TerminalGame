# ROADMAP：從 Demo 到可玩 1 小時的 JRPG

目標：用 `TerminalGame.Tui` 做出一款**可完整遊玩約 60 分鐘**的文字 JRPG——多座村莊、分階裝備、多位夥伴、有冒險氛圍。

本文件同時是**跨 session 的工作交接單**：每完成一項就勾選，並在最後的「進度日誌」補一行。新 session 開始時，先讀本文件、`docs/DEVELOPMENT.md` 與 `docs/DESIGN.md`。

---

## 1. 內容規模（以 1 小時反推）

假設一場戰鬥 30–45 秒、對話與探索約佔 40% 時間：

| 項目 | 數量 | 備註 |
|---|---|---|
| 村莊／據點 | 3 | 各有商店、旅館、劇情 NPC；約每 20 分鐘換一次場景 |
| 野外／迷宮區域 | 4–5 | 村莊之間的路 + 最終迷宮 |
| 一般敵人 | 15–20 種 | 每區 3–4 種；後期可用強化版（換色＋改名＋新數值） |
| Boss | 3–4 | 每章結尾一隻，最終 Boss 兩階段 |
| 夥伴 | 3（含主角 4 人） | 每章加入一位，各有戰術定位 |
| 裝備 | 4 部位 × 4–5 階 | 每座村莊商店升一階；迷宮寶箱給「下一階」 |
| 技能 | 每人 4–6 個 | 依等級解鎖 |
| 戰鬥次數 | 約 60–80 場 | |

原則：**內容可以重複利用，系統不要每章重寫。**

### 故事骨架（暫定）

| 章 | 據點 | 區域 | 新夥伴 | Boss |
|---|---|---|---|---|
| 1 | 晨曦鎮 | 低語森林 | 琳（弓手／速度型） | 森林之主・巨蕈 |
| 2 | 河港村 | 沉船洞窟 | 巴爾（重盾／坦克） | 深潭水蛇 |
| 3 | 砂岩城 | 熾熱遺跡 | 小雪（治癒／輔助） | 遺跡守衛 |
| 終 | — | 魔王城 | — | 魔王（兩階段） |

每章節奏：村莊（劇情、補給）→ 野外（練功、寶箱）→ 迷宮（分岔／簡單機關）→ Boss → 新夥伴／新地點。每 5–10 分鐘要有「新東西」。

## 2. 架構

```
src/
  TerminalGame.Tui/     既有：純 UI 框架，不認識「遊戲」
  TerminalGame.Rpg/     遊戲規則，純 C#，不引用 Tui → 可單元測試、可 Monte Carlo 模擬
    Data/      *Def：唯讀定義（ItemDef, EnemyDef, SkillDef, CharacterDef…）與 ContentDb
    State/     可變狀態（PartyMember, Inventory, Flags, GameSession, SaveData）
    Battle/    BattleEngine（事件式）、BattleEvent、DamageFormula、敵人 AI
    World/     MapGraph、EncounterTable（M1）
    Script/    對話／事件腳本直譯器（M1）
  TerminalGame.Demo/    Scenes：把 Rpg 的狀態畫出來（日後可改名 TerminalGame.Game）
content/                JSON 內容檔（建置時複製到輸出目錄）
tests/
  TerminalGame.Tui.Tests/
  TerminalGame.Rpg.Tests/  規則與內容驗證測試
  TerminalGame.Demo.Tests/ 無頭終端的遊玩流程測試
tools/
  TerminalGame.Sim/        平衡模擬（M2）
```

### 關鍵設計決策

1. **Def 與 State 分離**：定義從 JSON 載入、全遊戲共用；狀態只存 id 與數值。存檔 = 序列化 State。
2. **戰鬥引擎事件式**：`BattleEngine.execute(action)` 回傳 `IReadOnlyList<BattleEvent>`；Scene 只負責收集輸入與「播放」事件（訊息、HP 條）。引擎不知道畫面存在。
3. **亂數可注入**：引擎吃 `Random`（或 `IRandom`），測試與模擬可固定 seed，結果可重現。
4. **內容驗證測試**：所有交叉引用（掉落物、技能、地圖出口、腳本中的 id）在測試中檢查，內容越多越重要。
5. **平衡靠模擬**：引擎可脫離 UI 執行，用 Monte Carlo 統計勝率、平均回合、剩餘 HP 分布。

### 第三輪：經濟（M4，第二次試玩回饋）

模擬器結尾的「Economy」表：照檢查點等級推進時，練等所需的隨機戰鬥＋Boss 給的錢，對上每個檢查點假設的裝備（舊裝備半價賣回、寶箱裝備免費）與多帶的消耗品。不足的部分會延到下一次購物（「covered」= 這次付得出的比例）。旅館與補貨沒有算進去，所以真實錢包會再薄一點。

| 購物點 | 調整前 covered | 調整後 covered |
|---|---|---|
| 空地 Lv5（銅劍、皮帽） | 50% | 63% |
| 森林之主前 | 50% | 100% |
| 沙洲 Lv9（第 2 階） | 22% | 61% |
| 底艙 Lv11 | 0%（欠款） | 94% |
| 前庭 Lv13（第 3 階） | 13% | 79% |
| 城內 Lv17 | 0%（欠款） | 100% |
| 魔王前 Lv19（第 4 階） | 2% | 100% |

原因：裝備每階約 ×2 價，但每場金錢成長較慢，錢／經驗比從森林的 0.45 掉到後期的 0.32；Boss 的經驗接近一整級，讓下一區需要打的場數變少；經驗是每個成員各拿全額，金錢卻要買 4 套裝備。

改動：敵人金錢 第 1 章 ×1.5、第 2 章 ×2、第 3 章 ×2、終章 ×2.2；森林之主 200→300、深潭水蛇 500→1200、遺跡守衛 900→2000；砂岩城武器防具店與神秘商人的裝備 ×0.8。戰鬥勝率與練等時間完全不變（經驗曲線與敵人經驗沒動；在預期等級時等級差規則不會觸發）。`BalanceTests.everyAreaPaysEnoughGoldForItsExperience` 守住每區錢／經驗比 0.55–0.9。

支線「幽靈船長」（溺死的水手×2＋幽靈船長，HP 2500、怕聖）：Lv14×4 第 3 階裝備 勝 94%（約 15 回合）、Lv15 勝 99%。

## 5. 給下一個 session 的交接

- **環境與踩過的坑**：見 [`docs/DEVELOPMENT.md`](DEVELOPMENT.md)（.NET 安裝、驗證指令、sln 換行、平衡比較的做法）。
- **M0 留下的設計決定**
  - 戰鬥是「逐人行動」制（每回合依速度±10% 排序，輪到誰誰就行動），不是 DQ 式「先全員下指令再結算」。
  - 勝利時存活的成員各自拿到全額經驗值；倒下的成員拿不到。
  - 爆擊只發生在物理攻擊（1/16，×1.5）；防禦狀態傷害減半，持續到自己下次行動。
  - 道具只能由我方使用；目前沒有復活效果（M2 可加 `Revive` EffectKind）。
  - 敘述文字（`attackMessage`、`useMessage`）放在內容 JSON，讓每隻怪物／技能有自己的台詞。
- **M1 留下的設計決定與已知缺口**
  - 腳本中的 `battle` 只有勝利才會繼續；戰敗由 `LocationScene` 統一處理（失去一半金錢、回到復活點）。
  - 選項按取消 = 選最後一項（慣例上是「不要／離開」）。
  - 任何角色都能裝備任何武器（還沒有職業限制）；可在 M2 加 `ItemDef.equippableBy`。
  - 沒有復活道具；倒下的成員要靠旅館或小屋休息恢復。
  - 平衡已用模擬器做過第一輪（見「平衡紀錄」），但還沒有人工試玩。
  - 戰鬥中多人隊伍面板沒有 HP 條，只有文字；4 人時寬度剛好。
- **M2 留下的設計決定**
  - 狀態只存在於戰鬥中（掛在 `Combatant` 上），戰鬥結束即消失，不進存檔；因此「解毒草」等只在戰鬥中能用。
  - 狀態在「持有者自己的回合結束時」結算：先扣毒傷，再讓每個狀態少 1 回合；在自己回合對自己施加的狀態，那一回合不扣。
  - 睡眠／麻痺而失去的回合由引擎內部自動跑完（`TurnSkippedEvent`），所以 `currentActor` 永遠是能行動的人，UI 與模擬器不用特別處理。
  - 增益與減益互相抵消（不疊加）；重複施加取較長的剩餘回合。
  - 屬性只在敵人身上（`weakTo`／`resists`）；我方的屬性抗性（例如護符）尚未實作，需要時可把 `elementRate` 擴充到 `PartyCombatant`（裝備加 `resists`）。
  - 日誌與閒聊全部由旗標推導（閒聊聽過 = 旗標 `banter_<id>`），存檔格式不變（仍是 version 1）。
  - 原本林間空地的「和琳說話」改由夥伴閒聊取代；晨曦鎮新增「廣場的旅人」播放隨機流言（提示火屬性、薄荷葉）。
  - `TextBlock.scrollOffset` 在繪製時會被夾住並寫回，呼叫端可以直接 ±1 捲動。
- **M3 留下的設計決定**
  - 世界觀：森林之主、深潭水蛇、遺跡守衛是魔王封印的三位守護者；黑霧侵蝕它們、打倒後黑霧飛回北方，第 3 章結尾魔王城浮起。
  - 新夥伴加入時等級 = max(腳本指定, 隊伍平均等級)，避免玩家練太多時新夥伴跟不上。
  - 武器限定角色（劍＝艾倫、弓＝琳、斧／鎚＝巴爾、杖＝小雪）；防具大多共用，少數限定（鎖子甲／鋼板甲／秘銀甲＝艾倫與巴爾）。
  - 每座城的商店賣下一階裝備；迷宮寶箱給更高一階（海盜彎刀、太陽之刃、聖劍等）。終章沒有城鎮，改由城門的神秘商人販售第 4 階。
  - 兩階段 Boss：第一型態倒下時由 `nextPhase` 在同一欄位接手，兩個型態的獎勵都給；`BattleScene` 換掉該欄的名字、圖與 HP 條。
  - 「自動」戰鬥用 `AutoPolicy`（spendMp = true），Esc 在下一個我方回合收回控制；狀態在指令框標題顯示。
  - 結局：打倒魔王後腳本 `travel` 回晨曦鎮，由晨曦鎮的 `onEnter`（`demonKingDefeated && gameCleared == 0`）播放尾聲；之後可以自由走動（`gameCleared`）。
  - 模擬器的 trip 會在戰鬥之間用治療魔法回血；同一個升級目標的多個房間只算一次時間。
- **已知缺口／M4 候選**
  - 沒有「離開迷宮」的道具或傳送，回城要走回去（每章迷宮最多 4–5 間，尚可接受）。
  - 戰鬥中 4 人時隊伍面板只有文字、沒有 HP 條（MP 三位數黏字已修正）。
  - 最終戰約 19 回合、遺跡守衛約 15 回合，偏長；人工試玩後可考慮降 HP、提高我方傷害。
  - 終章的地圖沒有城鎮，女神像只能休息與存檔，不能買恢復道具以外的東西（神秘商人有）。
- **M4 留下的設計決定**
  - 等級差規則都在 `Progression`：`expRate(memberLevel, enemyLevel)` 逐人逐敵計算（所以等級較低的成員會自然追上），`encounterScale(partyAverage, areaLevel)` 由 `WorldRules.encounterRate` 套用；「搜索」（forced）不受影響，想刷錢仍然可以。敵人的 `level` 因此不再只是顯示用，新增敵人時要填合理的等級。
  - `VictoryEvent.exp` 仍是敵人的全額經驗；每個人實際拿到的在 `VictoryEvent.shares`，戰鬥訊息會提示「等級遠高於對手，只得到 N 點經驗值」。
  - 支線不佔「目前目標」（日誌的目標只顯示一條主線），改用大事紀記錄接受與完成；NPC 的台詞本身會提醒去哪裡。
  - 回頭支線的寫法：城鎮 NPC `cases` 依旗標換台詞 → 舊地圖的 spot 用 `if: "flag:x == 1 && item:y == 0"` 出現 → 戰鬥＋`giveItem` → 回報時 `takeItem`、`giveGold`、`setFlag x 2`。「討伐 N 隻」可以用既有的 `addFlag` 計數。
- **步調旋鈕（若試玩後想放慢，都不需要改框架）**
  - 文字速度：`DialogueBox.charsPerSecond`（預設 30）與 `punctuationPause`（預設 0.18 秒），可在 Demo 建立訊息框時設定。
  - 遊戲長度：`locations.json` 的 `encounterRate`／遭遇表、`Progression` 的經驗曲線、敵人經驗值與金錢、商店價格；改完用模擬器重跑平衡並更新 `BalanceTests`。
- **下一步**：M4 打磨——人工試玩確認新經濟（尤其是第 2、3 章剛進城時買不買得起）、視回饋再加支線、戰鬥演出與轉場。
